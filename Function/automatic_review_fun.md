원문: “claude 와 grok 은 완성되었다고 gpt에게 전달”, “gpt는 다시 한번 더 디버깅오류 등을 다시 찾고”, “해당 작업을 수행한애 … 수정하라고 자동으로 이야기를 해주고 다시 수정을 하는 식”. D-R01: 보고·검토·원 담당자 수정·재검증 루프 — 최신 사용자 승인. D-R02: 3자 전체 읽기 전용 최종 검토 — 앞선 사용자 요구. D-R03: fun은 첫 계획 에이전트에만 적용 — 앞선 사용자 요구.

Context: 폴더 동의·공급자 연결·사용자 요청·모델 선택·수정 한도. Trigger: 작업 시작, worker 보고, GPT 지적, 한도 도달, 사용자 중지. 자동 수정 최대 횟수는 사용자가 실행 전에 입력하며 앱이 임의 기본값으로 채우지 않는다. 설정 가능한 코드 처리 범위는 0~20회. 실행 검증은 사용자가 지정한 npm 스크립트와 별도 동의가 있을 때만 수행한다.

구현 근거: `Workflow`, `GPTProvider`, `ClaudeProvider`, `GrokProvider`, `validateProject`, UI event panels. 테스트: `test/workflow.test.js`, `test/validation.test.js`의 원 담당자 재배정·의존 작업 재실행·수정 한도·질문 중지·같은 hash 최종 검토·검증 성공/실패·명령 중지 확인. 실제 공급자들은 호출하지 않았고 성공했다고 주장하지 않는다.

기록: `Function/<run-id>_fun.md`, `.control-tower/runs/<run-id>/state.json`, `events/`, `backups/`. 최근 상태에는 마지막 이벤트를 보관하고 전체 이벤트는 개별 JSON에 보존. 앱을 재실행하면 진행 중이던 기록은 interrupted로 표시한다. 관련 기능은 `project_workspace_fun.md`. 한계: 현재 worker는 텍스트 소스 스냅샷과 JSON 파일 변경 목록 방식이며 완전한 내장 터미널은 아니다. 시안 이미지를 worker에 자동으로 입력하는 연결과 worker별 독립 채팅·역할 교체는 미구현이다. 실제 공급자 버전·계정 권한과 이미지 품질·실사용 시나리오 검증은 남아 있다. 다음 작업: Grok 설치·로그인 후 실제 프로젝트 검증. 임의의 “오류가 절대 없다”는 보장은 하지 않는다.
