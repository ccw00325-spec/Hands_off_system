# AI 설정·자동 인계 · ROLE-020 · v0.2.0

사용자 요청에 따라 이전의 구현 역할 중복 허용과 수동 대체 AI 필수 정책을 새 설정에서 대체한다. 과거 실행 명세는 계속 읽을 수 있다.

```gherkin
Feature: 이해하기 쉬운 AI 설정
  Scenario: 기본 세 패널과 자동 모델 조회
    When 프로젝트의 AI 설정을 연다
    Then GPT는 control/debug/review/test를 맡는다
    And Cursor는 feature/debug/review를 맡는다
    And Claude는 ui/review를 맡는다
    And 01번 고정 컨트롤 타워 체크박스는 없다
    And 열기와 AI 변경 시 모델을 자동 조회한다
    And AI 이름으로 모델 선택을 안내하고 로딩과 실패를 표시한다
    And Cursor와 Gemini는 저장된 모델 또는 명시적으로 선택한 모델을 사용한다

  Scenario: 단일 구현 담당
    Given 한 패널이 기능 또는 UI 구현을 맡는다
    Then 다른 패널의 같은 체크는 비활성화된다
    And 저장 API에서도 구현 역할의 단일 담당을 검사한다
    And 디버깅과 검토와 테스트는 중복 배정할 수 있다

Feature: 남은 팀 AI의 자동 인계
  Scenario: 수동 대체 없는 복구
    Given GPT 40%와 Claude 10%가 확인되고 기능 담당 AI가 소진됐다
    When 별도 대체 AI가 지정되지 않았다
    Then 역할 적합도가 같으면 GPT부터 로그인과 모델을 확인한다
    And 같은 작업 ID와 명세와 저장된 소스와 완료 기준으로 요청한다
    And 호출 상한과 API 예산을 우회하지 않는다
    And 모두 사용할 수 없으면 저장된 코드를 보존하고 멈춘다

  Scenario: 낮은 한도와 Cursor UI 확인
    Given 최근 2분 안의 공식 잔여 한도가 5% 이하이다
    Then 다음 요청 전에 더 여유 있는 팀 AI를 찾는다
    And 미지원 또는 오래된 수치를 추정하지 않는다
    And 사용량 조회 실패 자체가 일반 작업을 막지 않는다
    When Cursor가 UI 구현을 시작하려 한다
    Then 현재 권장 설정의 안내와 취소 또는 진행을 묻는다
    And 기본 선택은 취소이며 취소 시 요청을 보내지 않는다

  Scenario: 기본 뮤테이션과 가이드
    When 앱을 열고 작업을 요청한다
    Then 뮤테이션 테스트는 기본 체크 상태를 유지한다
    And 미설정 프로젝트는 통과 대신 설정이 필요하다고 안내한다
    And 일반 테스트만 실행하려면 체크를 끌 수 있다
    And 실제 화면과 설명과 바로가기를 포함한 8개 가이드를 제공한다
```

검증: 단위·통합 157개, Electron 시나리오 40개. AI 계정·모델·한도 오류는 테스트용이고 Node 파일·테스트 실행은 실제다. 뮤테이션 UI는 테스트 보고서로 흐름을 확인했다. 공급자 내부 세션이나 저장되지 않은 부분 응답은 복원한다고 보장하지 않으며 마지막 저장 코드와 같은 요청으로 이어간다.
