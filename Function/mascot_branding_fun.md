사용자 요구: “정말 단순하게 … 박스를 들고 옮기는 것처럼 뭔가 일하는 … 컨트롤 타워가 아래에 일을 주는 … 대기시간”. 로고 최종 승인과 비공개 저장소 선택은 별도로 받았다. 기존 상세 로봇 시안은 적용하지 않고 최종 승인한 민트 캐릭터만 사용한다.

Context: 작업 없음·계획 중·기능/UI 배분·완료 보고·검토 중·질문 대기·실패·중지·실행 검증 대기·전체 완료. Trigger: 실제 workflow 이벤트 및 움직임 토글. Reaction: dispatch는 컨트롤→담당자, report는 담당자→컨트롤 방향으로 캐릭터가 이동한다. 실행 검증 대기는 전체 완료와 구분하고, 오류·중지는 이동을 멈춘다. 작업 중 역할 변경에도 해당 실행에 고정된 공급자 이름을 표시한다. 움직임 끄기와 OS의 reduced-motion 설정을 따른다.

```gherkin
@confirmed
Feature: 작업을 옮기는 캐릭터
  Scenario: S-B01 실제 작업 배분
    Given 컨트롤 타워가 기능 담당자에게 작업을 배분했다
    When dispatch 이벤트가 기록된다
    Then 캐릭터가 박스를 들고 컨트롤 타워에서 기능 담당자 방향으로 이동한다
    And 텍스트는 실제 실행 상태를 표시한다

  Scenario: S-B02 완료 보고 전달
    Given UI 담당자가 파일을 저장하고 완료를 보고했다
    When report 이벤트가 기록된다
    Then 캐릭터가 UI 담당자에서 컨트롤 타워 방향으로 이동한다

  Scenario: S-B03 검증이 남은 결과
    Given 코드 검토는 통과했지만 실행 검증이 완료되지 않았다
    When 상태가 awaiting_validation으로 바뀐다
    Then 캐릭터는 실행 검증 대기를 표시한다
    And 전체 완료를 표시하지 않는다
```

기존 사용자 데이터 폴더 `agent-control-tower`와 appId는 유지해 제품 이름 변경 때문에 기존 인증과 프로젝트를 잃지 않도록 한다. 승인된 PNG와 프롬프트는 `docs/branding/mascot.md`에 기록한다. UI는 래스터 이미지에 CSS 이동·호흡 동작을 적용하며, 개별 관절을 다시 그린 애니메이션이나 스프라이트 시트는 이번 구현에 포함하지 않는다.
