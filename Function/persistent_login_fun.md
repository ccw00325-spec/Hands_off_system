사용자 원문: “터미널 환경에서 로그인되어있는것이 연동이 가능하다면 즉시 로그인”, “한번 로그인을 하면 지속”, “7일동안 접속이없는경우”. 추가 질문에 대한 사용자 확정 답: **“이 앱에서 연결 상태를 다시 확인하고, 인증이 유효하면 계속 사용 (권장)”**. D-S01은 CLI 로그인 재사용, D-S02는 7일 미사용 후 재확인, D-S03은 강제 CLI 로그아웃을 하지 않는다는 이 답의 범위이다.

Context: 저장 연결 있음·없음·만료·네트워크 실패·7일 미사용·로그인 진행·브라우저 복귀·승인 코드 필요. Trigger: 앱 시작, 실제 사용자 입력, 연결하기, 다시 로그인, 브라우저 다시 열기, 승인 코드 전달, 취소. IP를 같은 기기의 인증 근거로 사용하지 않는다. 설치 ID는 표식이며 자격 증명이 아니다. 자체 GPT는 OS 암호화 저장과 자동 refresh, 다른 CLI는 해당 원본의 저장소와 갱신을 유지한다.

| 조건                             | 반응                                                              |
| -------------------------------- | ----------------------------------------------------------------- |
| 유효한 기존 Claude/Grok CLI 연결 | 새 로그인 없이 재사용                                             |
| 7일 미사용                       | 공식 상태를 재확인; 유효하면 계속                                 |
| 연결 확인 실패                   | 기존 인증정보를 지우지 않고 확인 필요 표시                        |
| CLI가 승인 URL 제공              | 앱의 브라우저 다시 열기 제공; URL을 로그·renderer에 전달하지 않음 |
| CLI가 승인 코드 입력 요구        | 한 줄 코드 입력을 원본 CLI stdin으로 전달; 화면 값 즉시 제거      |
| 취소                             | 앱이 시작한 로그인 시도만 중단; 로그아웃 명령은 호출하지 않음     |

구현: `PersistentSession`, `LoginFlow`, `BrowserOpener`, `ClaudeConnection.connect`, `CursorConnection.status/connect`, `ChatGPTAuth.access`, main 복원 IPC. 검증: `test/session-login.test.js`, `test/cursor.test.js`, `scripts/smoke.mjs`, 실제 Claude 상태·`/usage` 및 Cursor 인증·모델 설정 메타데이터. 사용자 확정에 따라 Grok 담당은 Cursor 계정으로 연결한다. 세 AI 연속 추론과 신규 계정 승인은 미검증이다. 한계: CLI가 자체적으로 여는 최초 브라우저는 시스템 기본 브라우저이고 앱의 Chrome 선택은 자체 링크 및 다시 열기에 적용된다. 서비스의 추가 인증은 원본 화면에서 처리한다. 기존 OAuth를 읽지 않는 bare 실행 옵션을 제거했다. 관련 기능은 `agent_login_fun.md`, `usage_status_fun.md`, `cursor_grok_fun.md`.
