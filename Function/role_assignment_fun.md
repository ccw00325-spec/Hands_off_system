원문: “컨트롤 타워에 누구를 세울지 기능구현, UI 구현 등 AI 솔루션도 어떤 AI를 사용할지 고를 수 있도록, 변경할 수 있도록”. D-R01은 세 역할의 AI 선택·변경, D-R02는 기존 프로젝트 관리 안에서 배치 저장, D-R03은 fun을 첫 계획 담당자에게만 전달한다는 기존 사용자 지침 유지다. 실행 중 배치 유지와 다음 실행부터 변경은 진행 중 보고의 담당자를 보존하는 구현 방식이며 UI에 명시한다.

Context: 미연결 AI 배정, 연결된 AI 배정, 한 공급자가 여러 역할 수행, 작업 진행 중 변경, 프로젝트 전환·재실행. Trigger: AI 역할 변경, 각 패널의 AI 변경, 배치 저장, 작업 시작. Reaction: 화면의 공급자 이름·상태·아이콘과 실제 요청 경로가 같은 배치를 따른다. 미연결 AI도 배정 가능하지만 해당 연결·모델이 없으면 작업 시작을 막는다. 배정하지 않은 AI의 로그인은 요구하지 않는다. 같은 공급자를 여러 역할에 배정하면 세 역할의 별도 세션이며 “서로 다른 세 AI”로 주장하지 않는다.

```gherkin
@confirmed
Feature: 역할에 사용할 AI 변경
  Scenario: S-R01 컨트롤 타워 변경
    Given 사용자가 Gemini를 컨트롤 타워로 배정했다
    When 새 작업을 시작한다
    Then fun 전체 지침은 Gemini의 계획 요청에만 전달한다
    And 기능·UI 요청과 검토는 각각 선택된 공급자로 전달한다

  Scenario: S-R02 실행 중 다음 배치 변경
    Given Gemini 컨트롤 타워로 작업이 진행 중이다
    When 사용자가 다음 배치의 컨트롤 타워를 Claude로 바꾼다
    Then 현재 작업의 계획·검토·보고는 Gemini 배치를 유지한다
    And 저장된 다음 배치는 프로젝트 재실행 후에도 Claude로 복원한다
```

구현: `roles.js`, 각 provider의 plan/build/review, main의 실행 옵션 캡처, renderer 역할 설정. 기존 작업 프로토콜의 `gpt/grok/claude`는 기록 호환성을 위한 컨트롤·기능·UI 역할 ID로 유지한다. 실제 공급자는 `options.roles`에 기록하며 사용자 화면과 이벤트는 해당 이름으로 표시한다. 근거: `test/roles-gemini.test.js`, `scripts/smoke.mjs`. 실제 서비스 추론을 테스트 공급자 응답으로 대신 주장하지 않는다. 이미지 생성은 기존 개인 OpenAI API 경로를 유지하며 다른 공급자에게 이미지 생성 기능을 자동 부여하지 않는다.
