구현 근거: `Workspace`, `Projects.grant/revoke`, main의 폴더·이미지 IPC, renderer의 folder-consent와 folderbar. 검사: `test/workspace.test.js` 및 `scripts/smoke.mjs` 실제 임시 폴더 검사 통과. 코드·이미지 저장은 프로젝트 내부, 인증정보는 별도 OS 보호 저장. 미구현: 여러 root를 하나의 프로젝트에 추가하는 기능. 사용자 제외 사항은 아님.

한계·리스크: 앱 파일 경계 검사는 OS 샌드박스가 아니며, 다른 프로세스에 대한 시스템 차원의 접근 통제를 제공하지 않는다. 기존 파일 외부 변경은 해시 비교로 거부한다. 전체 다중 파일 적용은 트랜잭션이 아니므로 저장 중 실패 시 일부 변경이 남을 수 있다. 수정 전 백업과 변경 이벤트를 기록한다. 폴더 선택과 동의 확인 간 대기는 코드에서 관찰된 10분 제한이며 사용자 지정값으로 주장하지 않는다. 관련 기능: `automatic_review_fun.md`, `image_api_key_fun.md`. 다음 작업: 실제 계정·CLI와 연결한 실사용 검증. 조사 범위는 위 소스·테스트·실행 화면이며 승인 근거는 최신 사용자 메시지.
