# Agent Control Tower

Current release: **0.2.1**. The user approved a chat-first vertical agent desk: left folders/conversations, central controller conversation, right 2–4 vertically stacked provider cards. Each card combines a readable provider logo with accumulating task history. Logo/task selection opens the original AI terminal and composer in a native dialog; the controller card opens the same controller session. Workflow is on demand, never a permanently expanded graph. See [current release/layout policy](docs/release-policy.md); older design notes are historical.

Use the established black engineering palette and mint status. Curved links join the controller to workers; the approved box-carrying mascot traverses them on actual dispatch/report events in opposite directions. No synthetic progress. Top bell retains notifications; transient notices close after 10 seconds. Provider logos and labels follow the actual runtime route after authenticated quota fallback. Historical tasks keep their actual provider attribution. Large log dialogs preserve access to their close button and keyboard Escape. Narrow layouts stack the rail after the controller instead of shrinking provider targets.

Audience: a student building locally and later sharing the application on GitHub.
Primary task: connect official local CLI accounts, assign overlapping engineering roles and optionally one authenticated backup per panel, then request a project with explicit design and execution approval. Image generation uses a separately registered personal API key.

Theme: Terminal, adapted to the established control-tower layout. No ornamental gradients, fake shell output, or simulated success. Neutral black surfaces, restrained mint status, amber warnings. System Korean sans for prose, system monospace for technical labels. All colors and fonts consume CSS tokens. Keyboard focus, reduced motion, error, loading, disabled and empty states are explicit.

Startup: a centered native frameless white splash precedes the hidden workspace. A local SVG version of the mint carrier walks, trips, drops and picks up its parcel in a six-second loop. Reduced-motion is respected. Startup progress reflects completed stages and provider discovery results, not an invented time estimate. Model choices share an in-memory per-process catalog prepared at startup; account changes invalidate it. Never display the main window before catalog and renderer readiness.
