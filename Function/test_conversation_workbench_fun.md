# 테스트·대화 작업 공간 명세 · v0.7

결정 출처: 2026-11-03 사용자 요청. 가역적 레이아웃·문구는 위임받아 구현했다. 추가 확인 질문 없이 진행한다. 컨트롤 타워는 하단의 큰 패널, 작업자는 상단으로 해석했다.

```gherkin
Feature: 테스트 설계·실행 역할
  Scenario: 역할 체크 후 작업 요청
    Given 승인된 작업 폴더와 테스트 역할을 포함한 팀이 있다
    When 컨트롤 타워에 앱 제작을 요청한다
    Then 첫 계획 에이전트만 Fun을 로딩한다
    And 모든 요구사항에 연결된 ID·전제·입력·기대 결과·재현 절차와 파일을 계획한다
    And 구현 완료 후 테스트 담당자가 배정된 테스트 파일만 작성한다
    And 호스트가 실행 권한에 따라 실제 Node 또는 npm 검증을 실행한다
    And 실행 명령·종료 코드·출력·케이스 결과와 재현 절차를 저장한다
  Scenario: 미동의 또는 불완전한 실행
    Given 테스트 코드는 준비됐으나 실행에 미동의했거나 계획 케이스가 누락됐다
    When 검증을 시도한다
    Then 전체 완료나 전체 테스트 통과로 표시하지 않는다
    And 설정 동의 후 같은 파일 버전에서 테스트를 다시 실행할 수 있다
  Scenario: 앱 코드 변경과 담당 분리
    Given 여러 테스트 담당자 또는 이전 성공 결과가 있다
    When 파일을 배분하거나 소스가 변경된다
    Then 테스트 파일은 중복 배분하지 않는다
    And 테스트 담당자의 앱 파일 수정은 거부한다
    And 이전 성공을 변경된 코드의 성공으로 표시하지 않는다

Feature: 폴더별 대화
  Scenario: 새 프로젝트
    Given 사용자가 새 프로젝트를 누른다
    When 네이티브 폴더 선택과 파일 접근 동의를 마친다
    Then 폴더명 프로젝트와 새 대화를 만든다
    And 취소 시 빈 프로젝트를 남기지 않는다
  Scenario: 대화 복원과 패널 질문
    Given 폴더 아래 여러 대화와 각 AI 질문창이 있다
    When 대화를 선택하거나 앱을 다시 실행한다
    Then 해당 대화와 연결된 작업·응답을 복원한다
    And 다른 대화의 작업을 현재 대화 문맥으로 섞지 않는다
    And worker 질문은 읽기 전용이며 파일 변경은 컨트롤 타워에 요청한다

Feature: 터미널 작업 공간과 설정
  Scenario: 진행과 사용량
    Given 작업자가 위, 컨트롤 타워가 아래에 배치됐다
    When 실제 작업 전달·저장·보고·테스트 이벤트가 발생한다
    Then 각 AI 로그와 우측 단계가 갱신되고 캐릭터가 상태를 안내한다
    And 움직임 허용 시 패널 사이 상자 전달을 표시한다
    And 사용 한도는 실제 5시간/주간 값을 독립적으로 표시한다
  Scenario: 최초 설정과 개인정보
    Given 처음 실행하거나 다른 기기·OS 사용자다
    When 코드 실행 동의를 확인한다
    Then 실행 권한은 기본 미동의이며 현재 기기·사용자에만 저장된다
    And 앱의 대화·인증 데이터는 프로젝트 읽기·쓰기·소스 전송에서 제외된다
```

제한: 현재 JS/TS 파일 계획과 Node/npm 실행, TAP 케이스 이름 매핑을 지원한다. 브라우저 E2E는 준비된 프로젝트 실행기·스크립트가 필요하며 의존성을 자동 설치하지 않는다. 질문 응답은 독립 AI 요청으로 실제 사용 한도를 소비한다. 완전한 OS 셸·OS 격리·숨겨진 모델 사고 과정은 제공하지 않는다.
