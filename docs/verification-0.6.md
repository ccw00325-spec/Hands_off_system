## 실제 타이머

공식 Codex ChatGPT 로그인과 실제 모델 목록의 `gpt-5.6-sol`을 사용했다. 두 패널 모두 GPT이며 control/debug/review와 feature/ui를 나눴다. 요구사항 9개, Context·Trigger·Reaction·완료 기준·디자인 토큰·결정·가정 목록을 Fun 계약으로 검사했다.

코어는 호스트가 미리 작성하고 해시를 고정한 검사로 idle/start/pause/resume/complete/reset 및 1~3600초 범위 밖 입력을 확인했다. 실제 Electron 브라우저는 3초 설정, 시작, 1.1초 진행, 일시정지 유지, 재개·완료, 초기화, 0초 오류를 확인했다. 생성 AI가 검사 성공을 말하는 것만으로 인정하지 않았다.

24개의 실제 요청을 사용한 마지막 실험에서 세 차례 자동 수정 후 실행 검증과 최종 검토를 통과했다. 같은 GPT 계정의 독립 요청 두 개가 실제로 동시에 수행됐다. 마지막 상태 `completed`, `passed:true`, `deleted:true`, 최대 동시 요청 2다. 비동기 보고·원 담당자 수정·의존 작업 재연결·최종 검토를 실제로 거쳤다.

초기 실패도 있었다. 검사용 브라우저 시계가 실제 시간과 함께 흘러 검사 자체를 먼저 수정했고, 뒤이어 AI 검토가 입력·초기화·접근성 문제를 찾아냈다. 제한 도달을 완료로 숨기지 않고 다시 검증했다. 마지막 생성 폴더는 실경로·상위 경계·소유 표시를 확인한 후 삭제했다. 보고서와 무시된 테스트 데이터만 남으며 타이머 앱은 제품 소스나 패키지에 포함하지 않는다.

## 로그인과 역할

실제 Electron에서 Codex와 Cursor의 공식 로그인 URL 생성·열기 호출·취소·기존 인증 유지, 프로젝트 재시작 복원, 2·4패널·중복 역할, 실제 coordinator의 네 독립 검토 세션을 확인했다. `/model`은 실제 Codex 목록을 조회해 선택을 저장했다. 이 UI 테스트는 추론 공급자 fixture를 사용하며 유료 AI 호출은 하지 않는다.

별도 실계정 검사로 Claude와 Cursor/Grok에 빈 소스·파일 생성 없는 최소 manifest 요청을 보냈고 성공했다. Grok 실제 모델은 `grok-4.7[context=256k,reasoning_effort=high,fast=true]`였다. 첫 호출에서 응답 후 프로세스 종료보다 임시 폴더 삭제가 앞서던 Windows EBUSY를 발견해 종료 대기·제한된 삭제 재시도로 고쳤고 재검사했다.

다른 기기·OS 사용자 저장소는 복호화 전에 거부한다. 기존 폴더 동의도 기기·사용자 결합이 다르거나 없는 경우 재동의가 필요하다. IP 변경 자체는 로그인 판단에 사용하지 않는다. 새로운 계정 로그인은 해당 사용자의 브라우저 승인이 있어야 하므로 대신 완료하지 않았다.

## 남은 사용자 확인

1. Gemini의 첫 Google 승인과, 새로운 Claude 사용자의 브라우저 승인은 직접 진행해야 한다. 현재 PC의 기존 Claude/Cursor/Codex 인증과 승인 URL·미인증 분기는 확인했지만 모든 신규 계정의 공급자 정책까지 대신 검증할 수는 없다.
2. v0.6 이전 프로젝트는 폴더를 다시 연결하고 동의해야 한다. 이후 같은 기기·사용자에서는 유지된다.
3. 다른 PC·배율·대형 프로젝트·서로 다른 세 공급자의 전체 프로젝트 동시 실사용은 별도 검증 대상이다. 현재 실제 전체 생성 실험은 GPT 두 세션이며 Claude/Grok은 최소 추론 검사다.
4. 공개 배포 전 코드 서명과 백신 평판 확인이 필요하다. 서명 인증서는 등록하지 않았다. 보안 잔여사항은 `security-0.6.md`에 명시한다.

worker별 별도 채팅과 이미지 자동 멀티모달 전달은 범위 밖으로 남아 있다. 텍스트 명세·자동 작업 전달과 별도 이미지 생성은 구현돼 있다. 모든 기능이나 임의 생성 앱이 무결하다고 보장하지 않는다.
