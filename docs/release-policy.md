# 배포·배치 관리 규칙

2026-11-03 사용자 지시에 따라 기존 기능을 유지하고 배포 기준을 `0.1.0`으로 재설정했다. 이전 `0.1.0` 실험 파일은 `Agent Control Tower 0.1.0.exe`였고 현재 파일은 `CW_Handsoff_sys 0.1.0.exe`다. 제품 이름·appId·사용자 데이터 경로를 유지한다. 과거 소스 커밋과 검증 문서는 이력으로 보존하며, 이전 실행 파일은 정리한다.

## UI

중앙 DOM 순서는 역할 표시 → **컨트롤 타워** → 하향 작업 전달 표시 → 작업자 패널이다. 화면·키보드 탐색 순서가 일치한다. 컨트롤 타워의 큰 로그·입력창과 2~4패널 구성을 유지하며 모든 화면 폭에서 같은 상하 관계를 따른다. 캐릭터는 실제 컨트롤/작업자 위치를 읽어 양방향으로 이동한다.

## 버전

- 현재 기준 `0.1.0`.
- 일반 수정은 patch만 올린다: `0.1.0 → 0.1.1 → … → 0.1.9`.
- patch가 9이면 다음 버전은 minor를 올리고 patch를 0으로 돌린다: `0.1.9 → 0.2.0`.
- `npm run version:next`가 package.json, package-lock.json 루트 버전, README 실행 경로를 함께 변경한다. UI 버전은 Electron의 실제 앱 버전에서 읽는다.
- 빌드만 실행하면 버전은 그대로다. Git tag·GitHub Release는 자동 생성하지 않는다.

## 이전 실행 파일 정리

`npm run package:win -- --config.compression=store` 성공 후 `postpackage:win`이 소스/ASAR/fuse 검증을 통과해야 정리 스크립트를 실행한다. `D:/Agent/release` 안에서 현재 버전을 제외한 `Agent Control Tower X.Y.Z.exe`, `CW_Handsoff_sys X.Y.Z.exe`, `builder-debug.yml`만 삭제한다. 새 파일이 없거나 폴더가 외부 정션으로 바뀌면 정리를 거부한다. 파일별 실경로를 먼저 확인하며 재귀 삭제를 사용하지 않는다.

같은 버전을 다시 빌드하면 현재 실행 파일을 갱신하고 이전 번호 파일을 쌓지 않는다. 현재 버전의 `win-unpacked`는 빌드·강화 옵션 확인용으로 남긴다. 임의 파일·소스·프로젝트·사용자 인증 저장소는 이 정리의 대상이 아니다.

Windows에서 실행 중인 구버전이 파일을 잠그면 제한된 재시도 후 종료 안내를 표시한다. 해당 앱을 종료한 뒤 `node scripts/prune-release.mjs`를 다시 실행한다. 정리 스크립트가 임의로 다른 앱을 강제 종료하지 않는다.
