# 최상단 컨트롤 타워와 배포 버전 재정리

결정 출처: 2026-11-03 사용자의 명시적 수정·삭제 요청. 이 문서가 이전 v0.7 명세의 상하 배치 결정을 대체한다.

```gherkin
Feature: 컨트롤 타워 우선 배치
  Scenario: 어떤 팀 크기로든 작업 공간 열기
    Given 팀 패널이 2~4개로 구성되어 있다
    When 작업 공간을 표시한다
    Then 큰 컨트롤 타워가 중앙 맨 위에 위치한다
    And 하향 전달 표시와 작업자들이 아래에 위치한다
    And DOM과 키보드 탐색 순서도 같다

Feature: 배포 버전과 이전 파일 정리
  Scenario: 현재 기준 재설정
    Given 기존 앱 기능과 사용자 데이터가 있다
    When 새 배포 파일을 빌드한다
    Then 현재 제품 버전은 0.1.0이다
    And UI에 실제 제품 버전을 표시한다
    And 기능·제품 식별자·사용자 데이터 경로를 유지한다
  Scenario: 이후 수정
    Given 현재 버전이 0.1.0 또는 0.1.9다
    When 다음 수정 버전을 반영한다
    Then 각각 0.1.1 또는 0.2.0이 된다
    And 단순 재빌드로는 버전을 증가시키지 않는다
  Scenario: 안전한 이전 파일 정리
    Given 새 실행 파일의 빌드와 소스 검증이 성공했다
    When 이전 배포 산출물을 정리한다
    Then release 내부에서 확인한 이전 제품 실행 파일과 builder-debug.yml만 삭제한다
    And 최신 실행 파일과 다른 파일은 보존한다
    And 새 빌드가 없거나 release가 외부 링크면 삭제하지 않는다
```
