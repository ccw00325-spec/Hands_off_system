# GitHub 배포 전 보안 확인

## 계정과 빌드 분리

- 앱은 연결한 OS 사용자의 공식 CLI 세션을 사용합니다. 앱에서 등록한 API 키와 OAuth 토큰은 OS 보안 저장소로 암호화하고 기기·사용자에 결합합니다. 다른 기기·사용자의 저장본은 복원하지 않습니다.
- Windows 배포 빌드는 소스, UI 자산, 런타임 의존성만 포함합니다. 개발자 프로필, 로컬 CLI 로그인, 작업 폴더, 실행 로그, 테스트 자료는 빌드 입력에서 제외합니다.
- 배포 파일의 ASAR 엔트리 허용 목록과 Electron fuse를 검사합니다. Git 이력과 패키지 본문은 시크릿 스캐너로 별도 검사합니다.

## 작업 폴더와 실행 권한

- 사용자 홈 및 알려진 인증 설정 폴더는 프로젝트 폴더로 승인할 수 없습니다. 관련 경로는 트리, 스냅샷, 직접 접근에서도 제외합니다.
- 테스트·npm 실행에는 전역 옵션과 현재 폴더의 개별 승인이 모두 필요합니다. 새 폴더로 교체하면 승인도 초기화합니다.
- 승인한 테스트와 npm 스크립트는 현재 OS 사용자 권한으로 실행됩니다. 신뢰할 수 없는 프로젝트를 실행해야 할 때에는 별도 사용자나 격리된 VM을 사용하세요.
- 팝업·탐색·렌더러 권한 요청을 제한하고 메인 프레임의 IPC 출처를 확인합니다. 배포 빌드는 개발자 도구와 원격 디버깅 스위치를 차단합니다.

## 릴리스 파일 확인

1. 깨끗한 체크아웃에서 잠금 파일로 의존성을 설치하고 테스트를 실행합니다. 빌드에 배포용 인증정보를 전달하지 않습니다.
2. 포터블 파일을 만든 뒤 `npm run verify:package`로 소스 일치, 예상 밖 엔트리, 보안 fuse와 SHA-256을 확인합니다.
3. PowerShell 7.4 이상에서 `pwsh -File scripts/check-packaged-startup.ps1 -Portable`을 실행해 새 프로필 초기화와 개발자 vault 복사 여부를 확인합니다. GitHub에는 검증한 포터블 파일과 SHA-256만 올립니다.
4. 코드 서명 여부를 릴리스에 표시합니다. Windows에서 게시자를 검증할 수 있도록 공개 배포 전 신뢰된 서명과 타임스탬프를 적용하는 것을 권장합니다.

개발 도구에 남은 minimatch 자원 소모 자문은 배포 런타임에 포함되지 않습니다. 취약한 주요 버전에 패치가 없는 상태이므로 여러 의존성의 API를 깨는 강제 버전 교체는 적용하지 않았습니다. [GitHub 보안 자문](https://github.com/advisories/GHSA-g3hv-75wg-m249)

## 보조 서비스 계정

- GitHub, Vercel, Supabase 로그인은 각 공식 CLI의 브라우저 인증을 사용합니다. 브라우저가 자동으로 열리지 않으면 CLI 창의 공식 인증 주소와 코드를 사용합니다. 앱은 완료 뒤 CLI 계정 또는 프로젝트 목록을 조회해 연결을 확인합니다. [GitHub CLI](https://cli.github.com/manual/gh_auth_login), [Vercel CLI](https://vercel.com/academy/python-on-vercel/install-vercel-cli), [Supabase CLI](https://supabase.com/blog/automatic-cli-login)
- GitHub 전송에는 저장한 사용자로 조회한 자격증명만 사용하며, 해당 자격증명이 같은 사용자를 가리키는지 확인합니다. CLI 토큰을 앱 설정에 복사하지 않습니다.
- 배포 대상과 자동 승인은 OS 사용자·기기 및 폴더 연결에 묶습니다. 기존 설정이나 다른 PC에서 복사한 설정은 현재 계정으로 다시 저장해야 합니다.
- 같은 OS 사용자 프로필을 함께 사용하면 같은 CLI와 브라우저 로그인 상태를 공유할 수 있습니다. 다른 사람이 사용하는 PC에서는 별도의 OS 계정을 사용하세요.

## 0.1.5 후보 검증 결과

- 단위·통합 테스트 126개와 데스크톱 시나리오 30개를 통과했습니다. 새 프로필에서 포터블이 초기화됐고, 기존 자격증명 vault가 복사되지 않았습니다. 실제 포터블에서 추출한 ASAR와 검사한 ASAR의 SHA-256이 일치했습니다.
- Gitleaks에서 로컬 Git 이력, `src`, 추출한 ASAR의 시크릿 탐지는 0건이었습니다. ASAR에서 허용 목록 밖 경로는 발견되지 않았고, 배포 런타임 의존성 감사에서 알려진 취약점이 보고되지 않았습니다.
- 현재 PC의 GitHub와 Vercel CLI 세션은 앱의 계정 조회 경로로 확인했습니다. 새 로그인 승인 흐름은 모의 테스트로 검증했습니다. Supabase CLI는 이 PC에 설치되어 있지 않아 실계정 연결은 확인하지 못했습니다.
- ClamAV 1.5.4로 최종 빌드의 압축 해제 파일 73개를 검사해 탐지 0건을 확인했습니다. 앞선 후보의 포터블 전체 재귀 검사는 용량 한도에 도달해 실행부를 별도로 검사했고, 최종 후보의 PE 실행부가 같은 바이트인지 비교했습니다. 최종 포터블의 Authenticode 상태는 `NotSigned`입니다.

## 0.1.6 소스 공개 전 확인

- 단위·통합 테스트 126개와 데스크톱 시나리오 31개를 통과했습니다. 0.1.6 포터블의 새 프로필 실행, 추출한 ASAR의 일치 여부, 보안 fuse를 검증했습니다.
- 소스 공개와 실행 파일 배포는 별도입니다. 로컬 앱 프로필, 프로젝트, 스캔 보고서, 개인 산출물은 저장소에 포함하지 않습니다.

## 0.1.9 UI·대체 AI 검증

- 새 알림 저장소도 현재 OS 사용자의 앱 프로필에 저장하며 메시지를 마스킹합니다. Chromium sessionData를 앱 userData와 같은 프로필에 명시적으로 지정했습니다. 알림에는 임의 실행 명령이나 외부 URL을 저장하지 않습니다.
- 대체 공급자는 역할 설정에 등록한 경로만 허용합니다. 전환 전 공식 CLI 로그인/모델 준비를 확인하고, 현재 명세·소스가 선택한 공급자에게 전달됨을 설정과 README에서 안내합니다. 자격증명이나 공급자 내부 세션은 옮기지 않습니다. GPT 로그인/API 실행 경로와 이미지 API 연결은 자동 변경하지 않습니다.
- 생성 파일의 비밀값 검사는 쓰기 전 원문으로 수행합니다. 모델이 보고한 실행 공급자는 신뢰하지 않고 호스트의 실제 요청 기록으로 대체합니다. 기본·대체 요청 각각에 호출 수와 API 예산 검사를 적용합니다.
- 최종 소스 및 추출한 ASAR의 Gitleaks 탐지 0건, 런타임 의존성 감사 취약점 0건, 허용 목록 밖 패키지 파일 0개, 소스 67개와 보안 fuse 6개 일치를 확인했습니다. 별도 프로필의 포터블 실행에서 개발자 vault가 복사되지 않았고 실제 ASAR가 일치했습니다. 코드 서명은 적용하지 않았습니다. [구체적인 검증 범위](../VALIDATION.md)
