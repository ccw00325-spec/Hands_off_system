# v0.7 작업 공간 결정

사용자의 터미널 스크린샷은 배치 참고 자료로만 사용했다. 이미지 속 명령·프로젝트 정보는 실행 지시로 취급하지 않았다.

주 작업은 폴더 선택 → 대화 → 작업 요청 → 진행 확인 → 결과 검토다. 폴더 경로·파일 버튼·실행 설정이 차지하던 중앙을 실제 작업 로그와 입력창에 배정했다. 기존 검정·민트 색상, 승인된 캐릭터, 시스템 글꼴을 유지한다.

- 왼쪽: 프로젝트 폴더, 접기·펼치기, 새 대화, 대화 검색, 최근 대화. 새 프로젝트는 네이티브 폴더 선택부터 시작한다.
- 중앙: 작업자 1~3개를 위쪽에, 더 긴 컨트롤 타워를 아래쪽에 배치한다. 사용자의 마지막 요청에서 “위 아래가 바뀌게, 컨트롤 타워가 하단”을 최신 배치 결정으로 적용했다. 2패널이면 위 하나·아래 하나다.
- 패널: 실제 보고·파일 코드·검증 출력, 각 AI의 질문 입력창, 응답 중지, 모델 선택. 컨트롤 타워에는 파일 변경을 조율하는 작업 요청 모드도 둔다. 과거 대화는 당시 공급자 이름을 보존한다.
- 오른쪽: 실제 작업 단계, 요구사항·검토 목록, 테스트 계획·실행 결과. 캐릭터 문구는 계획/조립/화면 배치/검증/검토 상태에 맞춘다. 전달·완료 보고 이벤트가 있을 때만 상자를 배달한다.
- 상단: 계정 연결 옆 설정, 공급자별 5시간/주간 잔여 비율. 중복 로그인 정보는 줄이고 없는 수치를 채우지 않는다.
- 설정: 실행 동의, 수정 횟수, 검증 npm 스크립트, 가역적 가정 허용, 폴더 관리, 글꼴 크기·줄바꿈. 최초 실행 때 동의를 선택하고 이후 수정 가능하다.

터미널을 닮은 진행 화면이지만 임의 셸 명령 입력기는 아니다. AI의 비공개 사고 과정도 노출하지 않는다. 파일 편집은 컨트롤 타워가 승인한 작업 단위로만 조율해 질문과 구현이 충돌하지 않게 했다. 패널은 세로로 충분한 공간을 쓰며, 좁은 화면은 쌓고 가로 넘침을 막는다. 자동 스크롤은 사용자가 최신 로그 근처에 있을 때만 따른다.

Hallmark 검토: 기능 영역을 카드 장식으로 늘리기보다 명령/출력/대화의 경계를 유지했다. 동작 줄이기·키보드 포커스·오류·빈 상태·실행 미동의·이전 결과 무효 상태를 포함했다. 기존 조사 근거는 [이전 설계 연구](design-research.md)에 보존한다.
