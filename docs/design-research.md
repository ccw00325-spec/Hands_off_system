# 작업 공간 재구성 · 2026-11-03

필요는 현재 프로젝트·누가 무엇을 하는지·어디가 막혔는지·어떤 파일이 바뀌었는지를 한 화면에서 파악하는 것이다. 공급자와 작업 세션을 구분해야 구독 하나로도 쓸 수 있다. 아래는 실제 사용자 인터뷰 결과가 아니라 기존 요구와 공개 소스를 참고한 설계 가설이다.

| 공개 근거                                                                                             | 관찰                           | 반영                                                 |
| ----------------------------------------------------------------------------------------------------- | ------------------------------ | ---------------------------------------------------- |
| [VS Code Sessions layout](https://github.com/microsoft/vscode/blob/main/src/vs/sessions/LAYOUT.md)    | 탐색·작업·보조 정보의 구분     | 좌측 프로젝트·파일, 중앙 세션, 우측 진행·검토·변경   |
| [Zed parallel agents](https://github.com/zed-industries/zed/blob/main/docs/src/ai/parallel-agents.md) | 프로젝트별 독립 문맥·동시 실행 | 로그인 하나와 여러 세션 구분, 실행 배치 고정         |
| [Electron 보안](https://www.electronjs.org/docs/latest/tutorial/security)                             | 권한·원격 컨텐츠·IPC 제한      | 완전한 터미널 대신 실제 이벤트·검증된 파일 변경 표시 |

상표에 역할을 고정하지 않는다. 상단 control 하나와 아래 1~3개 worker를 두고 기능·UI·디버깅·검토를 조합한다. 같은 역할 중복과 같은 공급자 반복은 실제 라우팅에 반영한다.

검정·민트 토큰과 승인된 캐릭터를 유지하고 대형 빈 공간을 줄였다. 큰 화면에서는 패널을 고정하고 로그만 스크롤한다. 작은 화면에서는 문서 흐름으로 돌아가 조작이 가려지지 않게 한다. 실제 Electron에서 320·375·414·768·900·1440·1920px 가로 넘침을 확인했다.

목록은 실제 run 상태에서 채운다. 완료 보고와 실행 검증 통과를 구분하며 가짜 진행률이나 내부 추론 공개를 주장하지 않는다. 단계·담당자·저장 파일·검증 결과·보고만 표시한다. 실행 중 배치 변경은 다음 작업에 적용한다.

모델은 패널별 설정에서 현재 공급자의 목록을 조회한다. Claude는 공식 CLI 별칭이며 계정 사용 권한을 보장하지 않는다. 모달 안에서 연결 설정으로 복구할 수 있다. 다른 PC의 배율·해상도와 큰 프로젝트 장시간 사용은 후속 실사용 검증 대상이다.
